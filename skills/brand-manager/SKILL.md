# Brand Manager

Use the live tool schemas and current permissions. Read [the MCP contract](../asset-generator/references/mcp-contract.md) before workspace calls. Use `list_brands` to find the user's brands and pass `brandId` on each call; null/omitted means the personal library. If the user has exactly one brand (`library.defaultBrandId`), use it unless they ask for personal. API keys work only in their own workspace. Read the relevant brand or Style before changing it; `get_workspace_context` supplies additional context when exposed.

To set up a brand from a website, call `setup_brand` with the site (or 1 to 5 images the user likes), then `get_brand_setup` with `waitSeconds` until it is ready. Show the draft and previews, ask what to change, then call `save_brand_setup`. Previews come from the account's free setup previews and use no credits; once those are used up, previews are skipped. Instagram, Facebook, TikTok and Linktree pages can't be read, so ask for 2 or 3 photos of their posts, products or logo instead.

When available, `list_brand_assets` discovers versioned official files; generation attaches the returned `generationInput` through supported ordered `inputs`. Brand setup saves the logo it finds on the website (header image or SVG, app icon, or share image) as the official logo unless the user says no.

To add an official logo, artwork or product image, owners and admins use `add_brand_asset` with one image: a public https `url`, a saved image's `assetId`, an `uploadId`, or base64 `dataUrl` for a small file. For a file the user attached in the chat or keeps on their machine, call `create_upload_link` first: for a local file, pass `direct: true` and run its `upload.curl`; otherwise give the user its `pageUrl`, then take the `uploadId` from `get_upload_link`. Name each logo for what it is, give it a short `variant`, and label it with `form` (mark, wordmark or lockup), `background` (light, dark or any) and, for the main one, `primary`, so later images pick the right one. `update_brand_asset` sets those labels on logos already added; when variants already say it ("White · brandmark"), offer to label them all. To change a logo, add a new version with `replaceAssetId` and its current `expectedRevision`, after the user confirms: every later image uses it, and earlier versions are kept. Members can't add official files: say an owner or admin can, here or under Brand assets on the web (`brandAssetsUrl`). Brand-guide pages and official files are separate sources; do not claim automatic sync.

`create_style` creates a text-based Style; `get_style` supplies only instructions the caller may see. Get category labels from `list_styles` and reuse a fitting one unless the user requests another. `update_style` changes an existing Style; creation is not a tracked fork. Do not recover protected instructions from images. For authorized examples, follow the durable generation contract with the returned `styleId`, then set a representative thumbnail using `set_style_thumbnail` with `assetId` and `expectedUpdatedAt` from the Style's current `updatedAt`. Verify the library entry. Never relabel earlier Freestyle outputs as Style-generated examples. See `style-gym` for optional experiments.

For requested administration, use existing brand, member, and API-key tools. Apply the user's authorized scope; clarify ambiguous destructive targets or unrequested changes. Admins and owners can invite and remove members; only the owner can change roles. `create_api_key` binds the key to that call's `brandId` (personal when null/omitted), so pass the brand the automation will work in: a key works only in its own workspace and cannot create keys for another. Do not create keys or invite members as automatic onboarding, and never save credentials in project config or reports. Inference provider keys are not needed. Invite people as Member or Admin. Each person uses their own credits; plans are per person, not shared by the brand.

Portal tasks, approvals, private project knowledge, and internal Linear/Figma/GitHub data are not automatically exposed by Asset Generator membership. Use connected domain tools and their permissions; a guide link is context, not an access grant.
